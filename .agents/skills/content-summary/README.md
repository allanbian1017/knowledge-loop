# content-summary Skill

## Overview

`content-summary` is a **reference library** for the content intelligence pipeline. It provides shared rules and templates consumed by `ingest-newsletter`, `ingest-threads`, `ingest-youtube`, and `ingest-website`. It is never invoked directly.

This follows the same pattern as `gws-shared`: a central dependency that multiple skills read from, eliminating copy-paste duplication.

## Problem Statement

Before this library existed, summarisation rules, AI analysis structure, suggestion logging logic, and filename conventions were copy-pasted across `newsletter-summary`, `process-delegate-tasks`, and their output templates. Adding a new analysis field required updating three separate places, creating drift and maintenance risk.

## Solution

Extract all shared logic into five canonical reference files. Each ingest skill reads the relevant file(s) at the appropriate step using progressive disclosure (`> 📄 Read ../content-summary/references/...`).

## File Structure

```
content-summary/
├── SKILL.md                        # Index of reference files and when to use them
├── README.md                       # This file
└── references/
    ├── output_template.md          # Standard v5.0 report structure (Answer-First Pyramid)
    ├── summarise.md                # Language rules, Three-Zone rule, and low-cognitive-load guardrails
    ├── ai_analysis.md              # AI analysis field definitions and calibration instructions
    ├── suggestion_log.md           # Append format for $DATA_REPO/data/suggestions_pending.md
    └── filename_rules.md           # Path sanitisation and directory naming convention
```

## Reference Files

| File | When to read | What it provides |
|---|---|---|
| `references/output_template.md` | Before structuring the report | Standard v5.0 Answer-First Pyramid structure: 1-sentence conclusion + triage/action callout, 3–5 numbered `核心重點`, conditional `一張表看懂` table/diagram, and per-topic `<details>` accordions (`深入解構` + `對我的意義與來源資訊`) |
| `references/summarise.md` | Before generating any summary | Language rules referencing `$DATA_REPO/data/lang_preferences.md`, Inverted Pyramid (3s → 15s → 2m) hierarchy, Three-Zone rule with Just-in-Time inline analogies, and 6 low-cognitive-load guardrails |
| `references/ai_analysis.md` | Before generating AI analysis | Field definitions, `$DATA_REPO/data/goals.md` + `$DATA_REPO/data/user_preferences.md` calibration, and rubric grading delegation |
| `references/suggestion_log.md` | After generating AI analysis | Output entry format for suggestions generated by the rubric-grader skill; supports optional `SuggestionOutputPath` for parallel subagent isolation |
| `references/filename_rules.md` | Before writing any report file | Path sanitisation, `{SourceType}_YYYY_MM_DD/` directory convention |

## Do Not Invoke Directly

This skill has no trigger phrases. It has no executable procedure. If you find yourself writing "use content-summary to…", you are doing it wrong — use an ingest skill instead.

## Architecture Decisions

### ADR-0001: Reasoning Map Markdown Format Simplification

**Status**: Accepted · **Date**: 2026-07-23

**Context**: v4.0.0 Reasoning Map templates used Unicode tree-drawing characters (`├──`, `└──`, `│`) and plain-text arrows (`↓`) that rendered poorly in Markdown Preview — proportional fonts broke tree alignment, and `↓` with 2-space indentation collapsed into continuous text. Six emoji evidence tags (`📊 Data`, `📖 Research`, etc.) added visual noise and were largely redundant with the content itself.

**Decision**: Replace all three templates with standard Markdown list structures and remove emoji evidence tags from the output.

- **Linear Chain**: `Step N:` + `↓` → ordered list (`1.` `2.` `3.`)
- **Parallel Arguments**: `├──` `└──` tree → nested unordered list
- **Minimal**: Unchanged (already standard bullet list)
- **Evidence tags**: Removed from output; retained as internal LLM guidance for sub-bullet decisions (concrete evidence → include sub-bullet; pure reasoning → omit)

**Consequences**: Reasoning Map renders correctly across all Markdown previewers. Sub-bullets are now semantically meaningful. Loses at-a-glance evidence type classification, but content itself makes evidence type self-evident.

### ADR-0002: Upfront Reading Decision Placement for Immediate Triage

**Status**: Accepted · **Date**: 2026-07-30

**Context**: In v4.0.0, `Reading Decision` was located after `Reasoning Map` (line 50+). Triaging 15+ daily reports required scrolling past ~35 lines or reading through `TL;DR` first.

**Decision**: Move `## ⭐ Reading Decision` immediately below `## 🔖 來源 Metadata` (before `## 📝 TL;DR`).

**Consequences**: Enables <5-second triage without scrolling. Low-rated content can be skipped immediately.

### ADR-0003: Decoupled Internal CoT Reasoning from Visual Output Order

**Status**: Accepted · **Date**: 2026-07-30

**Context**: Rendering Zone B (`Reading Decision`) ahead of Zone A (`TL;DR`) visually might tempt the LLM to rate relevance before extracting facts.

**Decision**: Instruct LLM in system prompts (`summarise.md`) to perform Zone A fact extraction first in CoT internally, synthesize relevance second, and then render output starting with `Reading Decision`.

**Consequences**: Maintains zero-hallucination factual extraction integrity while serving top-of-file triage UX.

### ADR-0004: Forward-Only Report Template Migration Policy

**Status**: Accepted · **Date**: 2026-07-30

**Context**: 70+ historical report files exist in `$DATA_REPO/reports/` using the v4.0.0 layout.

**Decision**: Apply the new top-placed `Reading Decision` structure only to newly generated reports. Leave existing historical files untouched.

**Consequences**: Eliminates git noise on archived report files; downstream distillers safely handle both formats.

### ADR-0005: Reader-Centric Learning Section Placement Before Core Thesis

**Status**: Accepted · **Date**: 2026-08-19

**Context**: Core Thesis is author-centric — it reads like a defense brief explaining why the author's position works. The user's actual reading flow is: triage → context → **learnings** → then optionally verify the author's logic. Placing learnings after Core Thesis forces consuming the full argument chain before discovering what's learnable.

**Decision**: Place `## 🧠 What Can I Learn From It` between `## 📝 TL;DR` and `## 🎯 Core Thesis`.

**Consequences**: Learnings are visible within the first screenful after triage. Reader can stop after learnings if they don't need to verify the logic chain.

### ADR-0006: Zone A Classification for Source-Faithful Learnings

**Status**: Accepted · **Date**: 2026-08-19

**Context**: The new section could be Zone A (source-faithful extraction) or Zone B (personalized inference). AI Analysis already provides personalized relevance in Zone B.

**Decision**: Classify as **Zone A (Extraction)**. Learnings must be derived strictly from source content with zero external inference or personalization.

**Consequences**: Learnings are universally portable and not tied to current user goals. Self-verification check #6 enforces specificity.

### ADR-0007: Forward-Only Migration for What Can I Learn From It

**Status**: Accepted · **Date**: 2026-08-19

**Context**: Hundreds of historical reports lack the new section. Retroactive regeneration risks source unavailability and overwriting manual edits.

**Decision**: Apply the new section to newly generated reports only. Do not regenerate historical reports.

**Consequences**: Zero risk, zero effort on historical content. Old reports remain intact.

### ADR-0008: 5 Action Archetypes and Takeaway-Only Queue Bypassing

**Status**: Accepted · **Date**: 2026-09-30

**Context**: In September 2026, 100% of generated suggestions converged on saving prompt templates (`$DATA_REPO/data/prompts/*.md`) due to Goodhart's Law gaming (Prompt curation had an 84.5% historical acceptance rate). This prompt monoculture created review fatigue, wrapping general news and backend architecture into dummy prompts.

**Decision**:
1. Enforce 5 explicit action archetypes in `ai_analysis.md`: `JIRA_BACKLOG`, `ADR_DOC`, `PROMPT_TEMPLATE`, `TEST_FIXTURE`, and `TAKEAWAY_ONLY`.
2. Strictly restrict `PROMPT_TEMPLATE` to interactive tools (interview kits, coaches, judges), explicitly banning it for general news, politics, and abstract architecture.
3. Automatically route `TAKEAWAY_ONLY` suggestions to `$DATA_REPO/data/suggestions_filtered.md` and daily distillation, bypassing `$DATA_REPO/data/suggestions_pending.md` to keep the review queue 100% actionable.
4. Stage `JIRA_BACKLOG` as proposals in `suggestions_pending.md`, creating real Jira issues via Atlassian MCP (`createJiraIssue`) only upon user review acceptance.

**Consequences**: Eliminates prompt monoculture, preserves 100% actionable review backlog, and aligns suggestions with appropriate engineering artifacts.

### ADR-0009: Answer-First Pyramid & Single Merged Takeaway List (v5.0)

**Status**: Accepted · **Date**: 2026-11-24

**Context**: Stacking two metadata blocks, `Reading Decision`, `TL;DR`, `What Can I Learn From It`, `Core Thesis`, and `Reasoning Map` forced readers to scroll past three overlapping summaries and 150-character run-on sentences before understanding the core concept.

**Decision**: Reorganize the report template around **Answer First, Explain Later (3s → 15s → 2m)**:
1. **3-Second Top Callout**: Line 1 after `# {title}` is `> **🎯 一句話結論**` (≤45 chars, plain language), paired with 1-line star rating, source link, and minute-bounded `⚡ 下一步`.
2. **15-Second Core Skim**: Merge overlapping `TL;DR` + `What Can I Learn` into a single 3–5 item numbered `## 💡 核心重點` list (`≤1 sentence each`) plus a conditional `## 📊 一張表看懂` comparison table (`≤5 rows`, `≤18 chars/cell`).

**Consequences**: Readers grasp the bottom-line answer in 3 seconds and the entire mental model on one ~25-line screen with zero cross-section summary duplication. Supersedes the separate-heading layout of `ADR-0002` and `ADR-0005`.

### ADR-0010: Zone A+ Just-in-Time Context Bridge

**Status**: Accepted · **Date**: 2026-11-24

**Context**: Advanced sources (e.g., Stanford CME 295 LLM Systems) assume prior familiarity with domain terms (`SRAM vs. HBM`, `Prefill vs. Decode`, `KV Cache`). Strictly banning all external definitions left readers without context, while a front-loaded glossary still taxed working memory ("keep X in mind") 60 lines later.

**Decision**: Introduce **Zone A+ (Just-in-Time Context Bridge)** allowing concise textbook definitions or everyday analogies (`≤10–12 chars`, e.g., `SRAM（晶片內超快小桌面）`) inline at point of first use, while keeping all attributed claims and empirical benchmarks 100% source-faithful.

**Consequences**: Eliminates both unexplained jargon walls and off-screen glossary memorization without relaxing zero-hallucination guarantees on source claims.

### ADR-0011: Per-Topic Collapsible Accordions & Proportionality

**Status**: Accepted · **Date**: 2026-11-24

**Context**: Displaying 100+ lines of derivations, benchmarks, and 4-part `AI Analysis` uncollapsed overwhelmed visual scanning—and even a single giant `<details>` wrapper still dumped 60+ lines onto the screen when clicked.

**Decision**: Under `## 🔍 深入解構`, give each module/argument/news story its **own** `<details>` accordion (`≤5 total`), where `<summary>` states `N. Topic — 1-line conclusion` and expanding reveals **at most 3 short bullets** (`為什麼卡住 / 怎麼解決 / 數據與代價`) holding exact formulas and single-home benchmarks. Tuck `Personal Relevance` + `Metadata` (and `Raw Content` for YouTube/Threads) into compact footer `<details>` blocks, omitting tables/accordions on short posts (<300–500 words) when already covered upfront.

**Consequences**: Clicking any topic opens only 5–6 focused lines while preserving 100% of mathematical and engineering rigor.

### ADR-0012: Single-Suggestion Archetype Priority (ADR_DOC Monoculture Fix)

**Status**: Accepted · **Date**: 2026-11-26

**Context**: 54 of 56 pending suggestions were `ADR_DOC` (RCA `docs/rca/daily_workflow_rca_2026-11-26_V1.md`). Any architecture-flavored article matched `ADR_DOC`, the rubric scored it 6/6, and bulk acceptance fed back into the preference profile.

**Options**: (A) per-run gate in the grader that drops ADR/TAKEAWAY when any JIRA/PROMPT exists in the batch; (B) per-source-item priority applied by the worker.

**Decision**: (B). Each source item emits exactly one suggestion, chosen by priority `JIRA_BACKLOG`/`PROMPT_TEMPLATE`/`TEST_FIXTURE` > `ADR_DOC` > `TAKEAWAY_ONLY`. Lower-priority candidates are discarded, not logged. `TAKEAWAY_ONLY` is discarded entirely (not written to pending or filtered; existing filtered history is untouched), superseding ADR-0008's routing to `suggestions_filtered.md`. `ADR_DOC` additionally requires a named pending design decision in this repo, otherwise `TAKEAWAY_ONLY`.

**Consequences**: ADRs appear only when no concrete artifact fits. Enforcement is prompt-level; the rubric caps Preference Alignment for violating `ADR_DOC` items. No per-run deduplication or caps yet (open RCA items).
