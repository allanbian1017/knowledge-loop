## 1. Observed Problem

On 2026-09-03, 10 external intelligence documents (7 newsletters, 2 websites, 1 daily knowledge distillation) were produced during the daily workflow run. All 10 documents were written in **Traditional Chinese** (averaging 86.9% Chinese characters across 25,479 characters).

However:
1. The formal fallback rule in [`content-summary/references/summarise.md`](../../.agents/skills/content-summary/references/summarise.md) states: *"If the configuration is missing, empty, or invalid, default to **English**"*.
2. Inspection of [`data/user_preferences.md`](../../data/user_preferences.md) revealed that the `## Configuration` section and language preference keys were completely **missing**.
3. The user observed that the report was generated in Traditional Chinese, prompting an investigation into why the language behaved this way and how the dual-language configuration (`Preferred Report Language` and `Preferred Conversation Language`) should be systematically aligned.

## 3. Alternative Hypotheses Rejected with Evidence

### Hypothesis 1: *Source material was Chinese, causing subagents to mirror source language*
- **Rejection Evidence**: 8 of the 9 ingested sources were English publications (ByteByteGo, Anthropic documentation, Waymo engineering blog, Hugging Face papers, Superhuman, The Code, The Rundown AI, AI Inner Circle). Despite 100% English inputs, the subagents translated all summaries and analyses into Traditional Chinese.

### Hypothesis 2: *An environment variable or CLI parameter explicitly forced Chinese output*
- **Rejection Evidence**: Inspection of `daily-workflow` dispatch templates in `references/dispatch_spec.md` shows only `item_id`, `SuggestionOutputPath`, and `Report directory` are injected. No language flags or parameters are passed into the subagents.

## 4. Root Causes

### Primary Root Cause 1: Silent Overwrite in `review-suggestions` Skill
In [`review-suggestions/SKILL.md`](../../.agents/skills/review-suggestions/SKILL.md#L154-L186), Step 6 ("Regenerate preference profile") defines the canonical markdown structure for writing `data/user_preferences.md`:
- The template starts with `# User Preference Profile` followed directly by `## Summary Statistics`, `## Topic Preferences`, `## Action Type Preferences`, `## Shifting Interests`, and `## Explicit Preferences`.
- It omits the `## Configuration` section.
- Consequently, whenever the user completes a suggestion review cycle, `data/user_preferences.md` is rewritten from scratch, wiping out the user's persistent language configuration.

### Primary Root Cause 2: In-Context "Template Gravity" Overwhelming the Fallback Rule
While `summarise.md` specifies a fallback to English, the worker subagents operate under overwhelming in-context priming towards Traditional Chinese:
1. **Hardcoded Chinese Section Headers in [`output_template.md`](../../.agents/skills/content-summary/references/output_template.md)**:
   All structural headers (`## 來源`, `## 🔖 來源 Metadata`, `## ⭐ Reading Decision`, `## 📝 TL;DR`, `## 🧠 What Can I Learn From It`, `## 🎯 Core Thesis`, `> 一句話核心結論：`, `支撐論點：`, `## 🗺️ Reasoning Map`, `### 個人相關性（Personal Relevance）`, etc.) are written in Traditional Chinese.
2. **Chinese Anchors in [`data/goals.md`](../../data/goals.md)**:
   Subagents are required to ground Zone B judgements against `data/goals.md`. The goals are 100% Chinese (`建立 AI agent 系統`, `優化個人工作流程與生產力`). Evaluating against Chinese goals prompts the model to continue in Chinese.
3. **Chinese Procedures in Skill Definitions**:
   [`ingest-newsletter/SKILL.md`](../../.agents/skills/ingest-newsletter/SKILL.md) instructions are written in Traditional Chinese.
4. **Distillation Cascading**:
   [`daily-distiller`](../../.agents/skills/daily-distiller/SKILL.md) reads the 9 reports produced today. Because all 9 were in Chinese, it synthesized the final distillation in Chinese.

### Contributing Cause: Dual Terminology Split Across Documents
- [`AGENTS.md`](../../AGENTS.md#L19) specifies: `Preferred Conversation Language` vs. `Preferred Report Language`.
- Commit `d2e9735` stored: `Preferred Report Language` and `Preferred Conversation Language`.
- [`summarise.md`](../../.agents/skills/content-summary/references/summarise.md#L7) and [`daily-distiller/SKILL.md`](../../.agents/skills/daily-distiller/SKILL.md#L31) look for: `Preferred Output Language`.
- This naming divergence creates ambiguity across agent instructions.

## 5. Proposed Dual-Language Alignment Architecture

We formalize the **Dual-Language Contract** with clean separation between policy and configuration:
- **`AGENTS.md`**: Contains only the high-level governing rule (policy), preserving attention budget.
- **`data/lang_preferences.md`**: Dedicated single-purpose file for concrete language preferences, completely isolated from machine-rewritten statistical files.
- **Automated Lifecycle Hook**: Intercepts tool execution to guarantee `data/lang_preferences.md` always exists and contains valid keys.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          Dual-Language Architecture                         │
├──────────────────────────────┬──────────────────────────────────────────────┤
│ 1. Preferred Report Language │ External intelligence summaries, articles,   │
│                              │ newsletters, threads, daily distillations    │
│                              │ Default: English                             │
├──────────────────────────────┼──────────────────────────────────────────────┤
│ 2. Preferred Conversation    │ Internal documentation, plans, RFCs, RCAs,   │
│    Language                  │ agent conversational replies                 │
│                              │ Default: English                             │
└──────────────────────────────┴──────────────────────────────────────────────┘
```

### 5.1 Full Implementation Proposal

#### 1. Dedicated Configuration File: [`data/lang_preferences.md`](../../data/lang_preferences.md)
Create a dedicated configuration file at the repository root `data/` directory. By default, both report/post language and conversation language are set to **English**:

```markdown
# Language Preferences

- **Preferred Report Language**: English
- **Preferred Conversation Language**: English
```

*Rationale*: Isolating this from `data/user_preferences.md` prevents `review-suggestions` from ever touching or wiping language settings.

#### 2. Lifecycle Guard Hook: [`scripts/hooks/ensure_lang_preferences.sh`](../../scripts/hooks/ensure_lang_preferences.sh)
To ensure `data/lang_preferences.md` **always exists and is valid**, create an automated guard hook:
- **Existence check**: If `data/lang_preferences.md` is missing, auto-create it with default English values.
- **Schema & validity check**: Verifies both `- **Preferred Report Language**:` and `- **Preferred Conversation Language**:` exist and are non-empty. If missing or corrupted, repairs the missing keys.
- **Registration**: Registered in [`.agents/settings.json`](../../.agents/settings.json) under `BeforeTool` (for `run_command`) and `AfterTool` (for file edits):
  ```json
  {
    "name": "ensure-lang-preferences",
    "type": "command",
    "command": "./scripts/hooks/ensure_lang_preferences.sh"
  }
  ```
  This guarantees that even if a user or script deletes or corrupts `data/lang_preferences.md`, the hook immediately restores and validates it before any tool or subagent workflow proceeds.

#### 3. Update Policy in [`AGENTS.md`](../../AGENTS.md)
Keep `AGENTS.md` lean without hardcoding skill parameters:
```markdown
- **Documentation & Language Standards**:
  - Language settings are configured in `data/lang_preferences.md`.
  - Use Preferred Conversation Language for all internal docs (RCAs, plans, RFCs).
  - Use Preferred Report Language strictly for external content summaries.
```

#### 4. Standardize Skill Lookups to `data/lang_preferences.md`
- **[`content-summary/references/summarise.md`](../../.agents/skills/content-summary/references/summarise.md)**:
  Update the lookup to read `data/lang_preferences.md` for `Preferred Report Language` (defaulting to English).
- **[`daily-distiller/SKILL.md`](../../.agents/skills/daily-distiller/SKILL.md)**:
  Update Step 4 to read `data/lang_preferences.md` for `Preferred Report Language`.
- **[`study-github-repo/SKILL.md`](../../.agents/skills/study-github-repo/SKILL.md)**:
  Update Step 7 to read `data/lang_preferences.md` for `Preferred Report Language`.

#### 5. Automated Test Script: [`scripts/validate_language_config.py`](../../scripts/validate_language_config.py)
Create an automated test script enforcing:
1. `data/lang_preferences.md` exists, parses correctly, and has valid non-empty values for both keys.
2. The hook script executes cleanly and heals missing/corrupt files.
3. Skill files (`summarise.md`, `daily-distiller/SKILL.md`) correctly reference `data/lang_preferences.md`.

*(Note: Bilingual report header internationalization in `output_template.md` is explicitly deferred to [`backlog.md`](../../backlog.md) to maintain minimal scope).*
