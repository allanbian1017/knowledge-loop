# Plan: Path-Free Custom Sub-Agent Personas & Cross-Platform Sync

## Objective
Establish 6 custom sub-agent persona Markdown files (`.agents/agents/*.md`), implement `scripts/sync_subagents.py` to intelligently translate and project changes to `.claude/subagents/` and `.codex/subagents/`, and update workflow dispatch specs to use path-free subagent references with parameter injection via the first user message.

## Background Context
Currently, sub-agents are invoked using full file paths or implicit prompts, and the single prompt handles multiple formats (emails, threads, videos). We need to decouple the persona definitions from the dispatch mechanics, making them path-free, declarative, cross-platform compatible, and statically cacheable.

## Proposed Changes

### 1. Establish `.agents/agents/` as Single Source of Truth
- Create directory `.agents/agents/`.
- Create the following 6 Markdown files, using the **Universal AGY YAML Schema**:
  1. `newsletter_worker.md`
  2. `threads_worker.md`
  3. `website_worker.md`
  4. `youtube_worker.md`
  5. `rubric_grader.md`
  6. `distiller_reviewer.md`
- Each file must include:
  - Standard AGY YAML frontmatter (`name`, `description`, `tools`, `skills`, `enable_write_tools`, etc.).
  - A comprehensive system prompt defining role, rules, output format, and tone.
  - No string interpolation variables (like `<MESSAGE_ID>`); keep files 100% static for caching.
  - **Tool Scoping Rule**: The `tools:` array specifies domain-specific CLI/MCP integrations (`gws-gmail`, `agent-browser`, `yt2doc`). Native file system primitives (`view_file`, `write_to_file`) are automatically inherited via `enable_write_tools: true` and are omitted from `tools:` to prevent tool-converter errors across runtimes.


### 2. Implement Automated Cross-Platform Synchronization Script
- Create script `scripts/sync_subagents.py`.
- **Core Logic**:
  - Scans `.agents/agents/*.md` for source files.
  - Validates required YAML frontmatter structure.
  - **Claude Code Translation**: Maps frontmatter to Claude's native tool requirements in `.claude/subagents/<name>.md`.
  - **OpenAI Codex Translation**: Converts YAML metadata and persona prompt to native TOML configuration files (`.codex/subagents/<name>.toml` and `.codex/agents/<name>.toml`) with `name`, `description`, and `developer_instructions`.
  - Automatically prepends `<!-- DO NOT EDIT DIRECTLY: GENERATED BY scripts/sync_subagents.py -->` to output files.
  - Formats & writes targets to `.claude/subagents/<name>.md` and `.codex/subagents/<name>.md`.

### 3. Update Workflow Dispatch Specifications
- Update orchestration files (e.g., `docs/rfc/dispatch_spec.md` or equivalent daily-workflow scripts) to:
  - **Remove Paths**: Invoke subagents strictly by their logical name (e.g., `newsletter_worker`).
  - **Parameter Injection**: Pass dynamic variables (like `<MESSAGE_ID>`) explicitly as the **First User Message** or CLI task argument, rather than trying to inject them into the static persona file.

## Verification Plan
1. **Script Execution Validation**:
   - Run `python3 scripts/sync_subagents.py`.
   - *Expected*: Validates 6 files in `.agents/agents/` and syncs them intelligently to `.claude/subagents/` and `.codex/subagents/`.

2. **Schema & Formatting Validation**:
   - Check created subagent files in `.claude/subagents/` (should have translated YAML).
   - Check created subagent files in `.codex/subagents/` (should be pure Markdown, no YAML).
   - Run `python3 scripts/validate_skill.py` to ensure overall project compliance.
