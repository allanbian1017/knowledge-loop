# Plan: Daily Workflow Evaluation Harness

Create a repeatable evaluation harness for `daily-workflow` using fixed
GWS-shaped fixtures, an eval-only fixture adapter, run manifests, command
traces, deterministic validators, and the `skill-creator` benchmark/review
workflow.

RFC: [daily-workflow-evals.md](../rfc/daily-workflow-evals.md)

## User Review Required

> [!IMPORTANT]
> Fixed-data evals must never call live GWS or mutate Google Tasks. Live GWS
> checks are read-only smoke tests and must remain separate from deterministic
> regression evals. Validators must inspect command traces, not just
> agent-produced run manifests, to prove this boundary. V1 daily-workflow evals
> do not test live Gmail/newsletter behavior.

## Open Questions

- None for v1. The selected approach is fixture-adapter regression evals for
  `daily-workflow` first, then expansion to related skills after the
  orchestrator harness is stable.

## Proposed Changes

### 1. daily-workflow Eval Assets

#### [NEW] [evals/evals.json](../../.agents/skills/daily-workflow/evals/evals.json)

- Add skill-creator eval prompts for the orchestrator.
- Start with these eval cases:
  - `empty-delegate-list`: Delegate list is absent or empty.
  - `mixed-delegate-routing`: fixture contains Threads, YouTube, Website, and
    no-URL tasks.
  - `website-fetch-failure`: Website task fails both primary fetch and fallback.
  - `threads-login-wall`: Threads task is blocked by login wall.
  - `youtube-transcription-failure`: YouTube job exits non-zero.
  - `newsletter-step-boundary`: newsletter processing is invoked, skipped, or
    mocked without live Gmail calls.
  - `successful-full-run`: all Delegate URL source types complete and
    distillation/review are invoked.
- Include `expectations` for routing, safe completion ordering, failure
  isolation, no live GWS usage, newsletter step boundary handling, and correct
  final summary counts.

#### [NEW] [evals/files/](../../.agents/skills/daily-workflow/evals/files/)

- Add one fixture directory per eval case.
- Store GWS-shaped fixture files:
  - `tasklists.json`: output equivalent for `gws tasks tasklists list`.
  - `tasks.json`: output equivalent for `gws tasks tasks list`.
  - `expected_manifest_rules.json`: expected routing and completion behavior.
- Store source-content fixtures only when the eval needs report or
  source-faithfulness checks.

### 2. Eval-Only GWS Fixture Adapter

#### [NEW] [daily_workflow_eval_gws.py](../../scripts/daily_workflow_eval_gws.py)

- Implement an eval-only adapter that reads fixed fixture files and emits JSON
  shaped like GWS command output.
- Supported read commands:
  - `tasklists.list --fixture-dir <dir>`
  - `tasks.list --fixture-dir <dir> --tasklist <id>`
- Fail closed for unsupported commands, especially any mutation-like command.
- Do not call `/opt/homebrew/bin/gws`.
- Do not write to Google Tasks or any production state.

#### [MODIFY] [SKILL.md](../../.agents/skills/daily-workflow/SKILL.md)

- Add a short "Eval mode" note that points agents to the fixture adapter when a
  prompt explicitly says to run daily workflow in eval mode.
- Keep production instructions unchanged: real daily workflow execution still
  uses GWS and marks tasks complete only after reports and suggestion routing
  succeed.
- Add the run manifest requirement for eval mode only.

#### [MODIFY] [README.md](../../.agents/skills/daily-workflow/README.md)

- Document the difference between production mode, fixture regression mode, and
  live read-only smoke mode.
- Document where eval fixtures and run manifests live.

### 3. Run Manifest and Validators

#### [NEW] [validate_daily_workflow_run.py](../../scripts/validate_daily_workflow_run.py)

- Validate `.tmp/daily_workflow_runs/<date>/<eval_id>/run_manifest.jsonl`.
- Check:
  - Delegate discovery occurred when expected.
  - Task routing matches fixture expectations.
  - YouTube async launch occurs before synchronous processing.
  - `task.completed` happens only after `report.written` and
    `suggestion.routed`.
  - `task.failed` is never followed by `task.completed`.
  - Final summary counts match manifest events.
  - Eval mode contains positive fixture-adapter evidence.
  - Eval mode command traces contain no live `gws` commands.
  - Newsletter step is invoked, skipped, or mocked without live `gws gmail`.

#### [NEW] [validate_report_structure.py](../../scripts/validate_report_structure.py)

- Validate generated Markdown reports.
- Check:
  - Source type metadata is present and valid.
  - Required 7-layer sections exist.
  - Report path follows `reports/{SourceType}_YYYY_MM_DD/`.
  - Raw content policy matches source type.

#### [NEW] [validate_suggestion_routing.py](../../scripts/validate_suggestion_routing.py)

- Validate suggestion output generated by eval runs.
- Check:
  - Suggestions contain rubric score format `📊 {total}/6 (A:{n} P:{n} G:{n})`.
  - Suggestions route to pending or filtered output.
  - No eval output manually appends a pending suggestion without rubric routing.

### 4. Skill-Creator Benchmark Workflow

#### [NEW] daily-workflow eval workspace convention

- Use a sibling workspace for skill-creator runs:
  - `.agents/skills/daily-workflow-workspace/iteration-1/...`
- For each eval case, run:
  - `with_skill`: current `daily-workflow` skill.
  - `baseline`: no skill or an old skill snapshot, depending on whether the
    future implementation is adding evals only or modifying the skill.
- Save `eval_metadata.json`, `timing.json`, `grading.json`, `benchmark.json`,
  `command_trace.log`, and generated review HTML using the schemas from
  `skill-creator`.
- Preserve every shell command attempted by the executor in `command_trace.log`
  using the harness-owned command wrapper in v1. Do not accept native transcript
  export or agent-authored command summaries as v1 proof.
- Generate human review output with:

```bash
python /Users/allanbian/.gemini/antigravity/skills/skill-creator/eval-viewer/generate_review.py \
  .agents/skills/daily-workflow-workspace/iteration-1 \
  --skill-name "daily-workflow" \
  --benchmark .agents/skills/daily-workflow-workspace/iteration-1/benchmark.json \
  --static .agents/skills/daily-workflow-workspace/iteration-1/review.html
```

  section.

  cleanup.

  calibration.
- `review-suggestions`: pending/backlog split, feedback parsing, preference
  regeneration.
